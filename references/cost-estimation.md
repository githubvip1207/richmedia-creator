# 成本估算与核对

目标是尽量接近实际成本。优先补齐计费依据；不能因为缺少一个字段就直接返回“费用未知”，也不能以保守为由给出没有参考价值的跨度。所有范围都是所列假设下的估算，`range_is_guaranteed=false`，不能表示供应商保证封顶。

## 价格与依据

- `check` 显示价格快照日期。CLI `cost` 遇到超过 7 天的快照，尝试读取官方 Markdown 价格页并完整核对已支持模型的单价，成功后在任务目录保存供应商价格缓存。解析失败不覆盖旧单价，也不刷新核实日期；报价中记录失败及原日期。
- `doctor --pricing` 可主动复核并更新技能内的供应商单价快照。每家单独处理；页面无法访问或结构不能完整解析时，使用浏览器/搜索工具继续核对官方文档或官方计算器，再更新有证据的价格数据。脚本刷新失败不等于官方没有资料。
- 单价按公开刊例计算；有已确认的账户优惠、资源包抵扣或附加费时另行核对，不能把刊例金额说成实际扣款。

## 视频最低 Token

按以下优先级处理：

1. 从官方最低用量表或官方计算器取得对应模型、分辨率、宽高比和输出时长的值。通过 `estimate_context.minimum_billable_tokens` 和 `minimum_tokens_source` 传入；同时传 `minimum_tokens_spec`，结构为 `{model, resolution, ratio, duration}`，与本次估价值一致。模型使用技能别名。
2. 官方表或计算器因登录/访问问题无法读取时，使用 `models/video-cost-evidence.json` 保存的官方公开价格示例。公开示例是 16:9、输出 5 秒、输入 2～4 秒时的最低价格。按示例当时的单价反推 Token，保留公开金额舍入误差。
3. 其他输出时长/像素规格没有已核实门槛时，按上述锚点的输出时长与像素面积比例外推，以 `public_example_scaled` 记录。这是有来源的工程估计，尚未用完整最低用量表校准；不能把它称为官方精确门槛，也不能把舍入区间误解为外推误差范围。`result.estimate_quality=extrapolated`、`minimum_tokens_evidence.extrapolation_error=uncalibrated` 将其与文档依据估算区分；展示时必须一同说明，不能只展示狭窄金额区间。应继续尝试获取对应官方表格行来替换它。

脚本继续取 `max(公式 Token, 门槛估计)`，将方法、锚点金额/费率、来源、日期和外推公式保存在 `calculation.minimum_tokens_evidence`。手动门槛的网址必须属于对应供应商文档域或官方定价页链接的 ByteDance 飞书域；只附链接但未绑定规格会产生明确的不确定性提示。

官方表入口：

- [Seedance 2.0 系列最低用量表](https://bytedance.larkoffice.com/wiki/H0fUwHPxtiHayOk6CVpcZzKqnHJ?table=tblnV1KjhYJO12Zh&view=vewWPcN5zJ)
- [Seedance 2.5 最低用量表](https://bytedance.larkoffice.com/wiki/H0fUwHPxtiHayOk6CVpcZzKqnHJ?table=tblTUnmKaxBSqpU7&view=vewpCgsiHf)

## 输出尺寸与时长

- 指定比例：查对应模型的官方像素表，不能直接用输入像素代替输出像素。
- 自适应首帧/目标视频：先使用经过旋转信息、像素宽高比修正的显示比例。近似标准比例允许 1% 的比例偏差，例如 800×1424 可按竖屏表估算。
- Seedance 2.5 任意比例：保留显示比例，用同分辨率官方标准尺寸的像素面积范围推导偶数宽高，标注 `source_ratio_area_estimate`；这不是已核实的任意比例输出规则。
- 模型自行选择比例或目标尚不明确：按官方候选尺寸计算费用范围；多视频编辑/延长在提交前仍须明确目标，估价不替代任务歧义澄清。
- 补充 `output_dimensions` 时校验其与分辨率及固定比例的相容性，避免错用输入素材或其他分辨率的尺寸。
- 自动时长保留模型有效范围，同时输出 `scenarios` 中的若干时长及费用。已有需求明确期望秒数时，以 `preferred_duration` 标记相应情景，不改变 API 的自动时长参数。没有依据时不编造“最可能时长”。编辑任务按目标视频时长及约 0.4 秒误差缩小范围。

## 图层拆分

各输出图层可能具有不同像素档位，实际数量也无法提前确定。没有官方依据时，不因选择 1K 就宣称所有图层必然属于低档；继续保留完整费用范围，并给出含底图的 1、4、8、17 份输出的费用情景。展示总范围时同时提供这些情景，避免只留下跨度数十倍的数字。不得把情景数量说成模型承诺输出数量。

## 素材测量与变化

`ffprobe` 优先读取流时长、容器时长和 `duration_ts × time_base`，缺失时扫描包时间戳恢复；不要用假定的 24 FPS 倒推输入视频时长。编码宽高保留在 `width/height`，显示画幅写入 `display_width/display_height`。

本地素材继续校验哈希。新版实测的 HTTPS 素材在提交前重新读取计费规格并比较宽高、显示画幅、时长和可取得的文件大小；变化或无法重新测量时，先重新估价再确认。此检查针对费用相关变化，不保证远程 URL 内容永不变更。

## 生成后核对

提交记录保存不可变的报价快照。交付返回 `cost_comparison`，并在提交记录中保留：

- 视频：实际 `usage.completion_tokens`、按提交时刊例价计算的金额、相对预估范围的偏差，以及实测输出尺寸和时长。
- 图片/图层：实际输出数量、可读取的逐张像素档位和刊例金额；无法读取某张尺寸时保留该张的费用范围。
- `difference_percent_outside_estimate` 表示实际值超出预估范围的相对幅度；范围内为 0，低于范围为负值。它不是相对“最可能费用”的误差。

API 未给出实际用量或历史提交未保存报价快照时，说明可核对部分，不伪造账单。刊例核算与实际实付账单始终分开；发现较大偏差时，检查门槛、输出像素/帧数、价格和外推假设，并在后续报价前修正相应依据。
