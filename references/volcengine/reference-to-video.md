# Volcengine · 参考生视频（`operation=reference-to-video`）

## 生成要求

- 参数要求

| 参数 | 必须性 | 可选项 / 默认值 |
|---|---|---|
| `prompt` | 必需 | |
| `mode` | 必需 | `reference`：参考生成；`edit`：视频编辑。根据用户意图确定；无法区分时先澄清，无默认值 |
| `assets` | 必需 | 至少 1 份图片、视频或音频；编辑模式必须包含待编辑视频。按确认顺序提供素材，来源及限制见下文素材要求。 |
| `ratio` | 必需 | 参考生成及 2.0 视频编辑支持 `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive`，默认 `16:9`；2.5 视频编辑固定 `adaptive` |
| `duration` | 必需 | 2.5 支持整数 4～30 秒或 `-1`；2.0 系列支持整数 4～15 秒或 `-1`；默认 4 秒；2.5 视频编辑固定 `-1`，时长基本跟随待编辑视频 |
| `resolution` | 必需 | 参考[模型列表](../volcengine.md#模型列表)；用户未指定时默认 `480p`；已指定时按用户要求 |
| `generate_audio` | 必需 | 是否生成音频；默认 `false`；用户要求保留或生成对白、环境声、音乐或音效时设为 `true` |
| `estimate_context.target_asset_index` | 条件必需 | 编辑模式有多段输入视频时必需，从 0 开始按完整素材数组定位待编辑视频；单视频时可省略 |

- 素材要求

| 素材 | 格式及来源 | 尺寸、大小及时长 |
|---|---|---|
| 图片 | JPEG、PNG、WebP、BMP、TIFF、GIF、HEIC、HEIF；本地绝对路径或 HTTPS URL | 宽高均为 300～6000 px，宽高比 0.4～2.5；每张小于 30 MiB |
| 视频 | MP4、MOV，H.264 / H.265；可访问的 HTTPS URL | 宽高均为 300～6000 px，宽高比 0.4～2.5，总像素 407696～8295044；24～60 FPS；每段不超过 200 MiB |
| 音频 | WAV、MP3；本地绝对路径或 HTTPS URL | 每段不超过 15 MiB |

2.5 最多输入 30 张图片、10 段视频、10 段音频；视频和音频分别累计不超过 30 秒，单段为 2～30 秒。2.0 系列最多输入 9 张图片、3 段视频、3 段音频；视频和音频分别累计不超过 15 秒，单段为 2～15 秒。2.5 视频编辑模式的输入视频须为 4～30 秒。

脚本通过 `ffprobe` 实测素材信息；视频、音频的容器格式、视频编码与帧率以及各素材大小须能核验。本地图片、音频由 Python 在提交时编码为 Base64；含 Base64 的完整请求不得超过 64 MiB。本地视频不能通过 Base64 提交，须先由用户提供可访问的 HTTPS URL；本技能不自动上传视频。当前脚本不接受 `asset://` 或内联 Base64 素材。

2.5 参考生成支持仅输入音频；2.0 系列须至少有一张图片或一段视频。图片、视频和音频分别映射为 `reference_image`、`reference_video`、`reference_audio`，由脚本按素材类型填写，不能混入 `first_frame` / `last_frame`。

- 提示词优化

在主流程第 2 步落实本节生成要求时确定最终提示词，供估价和确认单使用；以下生成步骤只使用已确认的最终提示词，不再改写。
本能力要求使用 `sd25-pe` 优化提示词，仅应用与当前视频能力相关的规则，最终提示词须符合所选模型的要求。用户明确要求不优化时，按主流程将完整拼接的 `original_prompt` 原样赋给 `optimized_prompt`，不调用本地提示词优化。

参考生成须逐份说明素材用于主体外观、场景、动作、运镜或声音中的哪一项，明确新视频的主体、事件顺序与结局，不把参考视频当成待编辑母版。期望的新画幅或时长与参考视频不同且可能被误判为编辑时，按 `sd25-pe` 规则加入“请注意这不是视频编辑。”。

视频编辑须明确唯一母版、修改范围、保持内容及原时间线；其他素材仅辅助指定修改。2.5 编辑的画幅与基本时长由目标视频决定，不要求另改画幅或时长。只编辑声音时明确修改与保留的声音、口型时点及全部保留画面；需要先修改再续接的需求分成独立任务。

比例、分辨率、总时长和声音开关通过接口参数落实，不追加到提示词。输入素材顺序与提示词编号保持一致。

- 模式与费用

任务及估价 JSON 顶层均填写 `mode`；初始化记录中写入 `providers.volcengine.mode`，不写入 `intent` 或接口 `payload`。有 `estimate_context` 时，将其完整同步到该供应商的初始化记录、估价输入与提交 JSON。

2.5 的 `payload.omni_reference_task_type` 在参考生成时固定为 `reference`，编辑时固定为 `edit`；2.0 系列必须省略该字段，由提示词表达任务。`mode` 仅用于本地记录与校验，不直接发送给供应商。模型仍会结合提示词判定任务，参数不替代清晰的意图表达。

按[视频计费规则](../volcengine.md#文生视频图生视频参考生视频视频延长计费)估价，输入中必须包含当前 `mode`。所有输入视频时长都参与计费，不仅是编辑母版；优先使用匹配规格的官方最低计费门槛；不可访问时按公开价格示例估算，明确标注外推依据及未校准误差，规则和入参见本供应商文档的“预估成本”章节。

## 生成步骤

以下步骤在用户需要参考生视频且确认当前 Volcengine 方案后执行。

1. **构建任务 JSON：** 参考如下示例，基于用户输入的参数和确认的供应商、模型和能力，生成任务 JSON 数据。移除行尾注释后，将严格 JSON 直接追加到下一步命令的标准输入中。以下示例为参考生成；根据实际需求按顺序提供图片、视频或音频，在最终提示词中说明每份素材的用途。

   ```jsonc
   {
     "provider": "volcengine", // 必需：供应商，供脚本选择对应适配器
     "operation": "reference-to-video", // 必需：能力，供脚本选择接口及结果处理方式
     "mode": "reference", // 必需：reference 参考生成、edit 视频编辑；须与确认单一致，不提交给供应商
     "original_prompt": "参考熊猫图片、动作视频和环境声，生成熊猫在草地挥手的新视频", // 流程记录：用户原始提示词，不提交给供应商
     "assets": [ // 必需：本方案使用的素材，按输入顺序排列，由脚本解析，不直接提交给供应商
       {
         "id": "panda", // 必需：任务内唯一标识，供供应商引用；不是供应商素材 ID
         "kind": "image", // 必需：image、video 或 audio
         "source": "/absolute/path/panda.png", // 必需：执行前替换为实际 HTTPS URL；图片、音频也可使用本地绝对路径
         "purpose": "熊猫外观" // 必需：素材用途，只在这里记录一次
       },
       {
         "id": "motion", // 必需：任务内唯一标识，供供应商引用；不是供应商素材 ID
         "kind": "video", // 必需：image、video 或 audio
         "source": "https://example.com/motion.mp4", // 必需：执行前替换为实际 HTTPS URL；图片、音频也可使用本地绝对路径
         "purpose": "挥手动作与运镜" // 必需：素材用途，只在这里记录一次
       },
       {
         "id": "ambience", // 必需：任务内唯一标识，供供应商引用；不是供应商素材 ID
         "kind": "audio", // 必需：image、video 或 audio
         "source": "/absolute/path/ambience.wav", // 必需：执行前替换为实际 HTTPS URL；图片、音频也可使用本地绝对路径
         "purpose": "草地环境声" // 必需：素材用途，只在这里记录一次
       }
     ],
     "payload": { // 必需：火山引擎请求参数，脚本校验模型、参数及需求记录，解析外层 assets 并填充带角色的素材项后提交，不改写提示词；调用约定见脚本操作手册“提交生成”
       "model": "doubao-seedance-2-5-260628", // 必需：准确模型 ID；使用 2.0 系列时替换为对应 ID
       "content": [ // 必需：仅填写文本项；素材项由 Python 根据外层 assets 按顺序添加
         {
           "type": "text", // 固定：文本提示词
           "text": "图1仅定义熊猫外观，视频1仅定义挥手动作与运镜，音频1仅定义草地环境声。生成熊猫在阳光草地上朝镜头挥手的新视频。" // 必需：读取当前 request.json 的 optimized_prompt，须与确认单一致，不再改写
         }
       ],
       "omni_reference_task_type": "reference", // 必需：2.5 与 mode 一致，reference 或 edit；2.0 系列省略此字段
       "resolution": "480p", // 必需：所选模型支持的分辨率；用户未指定时默认 480p
       "ratio": "16:9", // 必需：所选模型支持的比例；默认 16:9；2.5 视频编辑固定 adaptive
       "duration": 4, // 必需：2.5 为整数 4～30 秒或 -1，2.0 系列为整数 4～15 秒或 -1；默认 4 秒；2.5 视频编辑固定 -1
       "tools": [{"type":"web_search"}], // 本例 2.5 默认开启；使用 2.0 系列且含素材输入时必须改为 []
       "generate_audio": true, // 必需：是否生成音频，默认 false；本例要求环境声，设为 true
       "watermark": false, // 固定：不加平台水印
       "return_last_frame": false, // 固定：不返回末帧
       "output_format": "mp4" // 固定：MP4；2.0 系列固定输出 MP4，省略此字段
     }
   }
   ```

   `service_tier` 固定省略，普通在线生成使用服务端默认行为。

   视频编辑时，将 `mode` 改为 `edit`，素材目录中明确待编辑视频；2.5 同时将 `omni_reference_task_type` 改为 `edit`、`ratio` 设为 `adaptive`、`duration` 设为 `-1`。例如提示词为“编辑视频1，将背景替换为雪山，保留熊猫外观、动作、机位与原视频时间线。”。多视频时须在 `estimate_context.target_asset_index` 中定位同一母版，不能仅依赖素材顺序猜测目标。

2. **调用脚本提交生成：** 使用上一步构建的 JSON 对象通过 `python3 "$SKILL/scripts/main.py" submit` 提交生成任务。使用本次任务文件目录 `$WORK` 作为 `--workdir`。脚本校验通过后将已确认的完整请求保存为 `$WORK/payload.json`；每次提交及其输出分别保存为 `submit-NNN.json` 和 `output-NNN/`。任务文件目录、提交序号及记录文件由脚本管理；记录返回的当前序号，并将提交文件路径记为 `$SUBMISSION`，供后续使用，不自行递增编号或拼接路径。命令示例见脚本操作手册。
3. **判断生成结果：** 调用 `python3 "$SKILL/scripts/main.py" status` 检查生成任务状态；`queued`、`running` 表示尚未完成，继续查询同一任务，不重新提交。如果失败则提示用户，如果成功则继续交付。提交结果未知时按脚本操作手册的失败处理规则核对原任务。
4. **交付结果：** 调用 `python3 "$SKILL/scripts/main.py" deliver` 获取并校验生成结果，将最终视频交付到启动本技能时所在的当前项目目录，并返回交付文件清单。完成后进入主流程的内容核验与结果展示步骤。

视频核验时，参考生成检查素材用途、主体对应关系、动作及声音是否符合确认要求；编辑模式检查修改区域、身份、保留画面、时间线和声音，2.5 编辑还须比较源视频与输出的画幅和实测时长。生成内容不承诺像素级或音轨字节级复刻。

接口参数依据：[创建视频生成任务](https://console.volcengine.com/ark/region:cn-beijing/docs/create-video-generation-task-api)。
