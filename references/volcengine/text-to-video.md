# Volcengine · 文生视频（`operation=text-to-video`）

## 生成要求

### 参数要求

下表列出官方 API 的可选值与默认值；用户已指定时按其要求。默认值与技能自行选择的方案参数须区分，确认单中列明实际提交值。

| 参数 | 必须性 | 可选项 / 默认值 |
|---|---|---|
| `content[].text` | 必需 | 视频生成提示词，对应 `optimized_prompt`；提交时须与确认单一致。文生视频仅提供文本项 |
| `resolution` | 可选 | 2.5 支持 `480p`、`720p`、`1080p`；2.0 支持上述档位及 `4k`；2.0 Fast / Mini 支持 `480p`、`720p`。均默认 `720p` |
| `ratio` | 可选 | `16:9`、`4:3`、`1:1`、`3:4`、`9:16`、`21:9`、`adaptive`；2.5 / 2.0 系列默认 `adaptive`，由模型根据内容选择画幅 |
| `duration` | 可选 | 2.5 支持整数 4～30 秒或 `-1`，默认 `-1`；2.0 系列支持整数 4～15 秒或 `-1`，当前火山官方页面未注明该系列默认值，方案中明确填写。`-1` 表示模型在有效范围内自动选择时长 |
| `generate_audio` | 可选 | `true`：生成同步音频，包括人声、音效或音乐；`false`：无声视频。默认 `true`；生成音频为单声道 |

### 提示词优化

- 在生成确认单前，使用 `sd25-pe` 优化提示词，仅应用与当前视频能力相关的规则，最终提示词须符合所选模型的要求；确认后的生成步骤不再改写提示词。
- 用户明确要求不优化时，按主流程将完整拼接的 `original_prompt` 原样赋给 `optimized_prompt`，不调用本地提示词优化，也不主动启用供应商服务端提示词优化。如所选模型无法关闭服务端优化，先说明限制并取得用户接受，再提交。
- 根据用户需求描述视频的主体、场景、动作、事件顺序、运镜及声音；需要对白时，建议用双引号标出对白内容。文生视频仅使用文字，不引用输入图片、视频或音频。
- 比例、分辨率、总时长和声音开关通过接口参数落实，不追加到提示词。

## 生成步骤

以下步骤在用户需要文生视频且确认当前 Volcengine 方案后执行。

1. **构建任务 JSON：** 参考如下示例，基于用户输入的参数和确认的供应商、模型和能力，生成任务 JSON 数据。移除示例中的全部注释后得到严格 JSON。下方 `payload` 按官方 API 编写；脚本调用方式见上方适配说明及脚本操作手册“提交生成”。

   ```jsonc
   {
     "provider": "volcengine", // 必需：供应商，供脚本选择对应适配器
     "operation": "text-to-video", // 必需：能力，供脚本选择接口及结果处理方式
     "original_prompt": "熊猫在草地上向镜头挥手，伴随鸟鸣和风声", // 流程记录：完整用户原话，不提交给供应商
     "payload": {
       // 必需：准确模型 ID，按已确认方案选择。
       // 2.5：doubao-seedance-2-5-260628
       // 2.0：doubao-seedance-2-0-260128
       // 2.0 Fast：doubao-seedance-2-0-fast-260128
       // 2.0 Mini：doubao-seedance-2-0-mini-260615
       "model": "doubao-seedance-2-5-260628",

       // 必需：输入内容列表；本例仅提供一个文本项，不提供参考素材。
       "content": [
         {
           // 必需：文本项固定为 text。
           "type": "text",

           // 必需：描述主体、场景、动作顺序、运镜及声音。
           // 读取当前 request.json 的 optimized_prompt，须与确认单一致，不再改写。
           "text": "一只熊猫坐在阳光下的草地上，先看向镜头，再抬起前爪缓慢挥手。镜头保持固定，远处传来鸟鸣和轻微风声。"
         }
       ],

       // 可选：输出分辨率；2.5 和 2.0 系列默认 720p。
       // 2.5：480p、720p、1080p。
       // 2.0：480p、720p、1080p、4k。
       // 2.0 Fast / Mini：480p、720p。
       "resolution": "720p",

       // 可选：输出画幅；2.5 和 2.0 系列默认 adaptive。
       // 可选 16:9、4:3、1:1、3:4、9:16、21:9、adaptive。
       // 文生视频中，adaptive 由模型根据内容选择比例。
       "ratio": "16:9",

       // 可选：输出秒数；本例明确生成 5 秒，不作为技能默认值。
       // 2.5：整数 4～30 或 -1，默认 -1。
       // 2.0 / Fast / Mini：整数 4～15 或 -1，方案中明确填写。
       // -1：由模型在有效范围内自动选择时长。
       "duration": 5,

       // 可选：是否生成同步音频；默认 true。
       // true：根据提示词和画面生成匹配的人声、音效或音乐。
       // false：无声视频。生成的音频为单声道。
       "generate_audio": true,

       // 可选：是否添加可见水印；默认 false。
       // true：右下角添加“AI 生成”标识；false：不添加。
       "watermark": false,

       // 可选，仅 2.5：输出格式，默认 mp4。
       // mp4 便于播放与分发；mov 面向高色彩精度后期，部分播放器不兼容。
       // 使用 2.0 / Fast / Mini 时省略此字段。
       "output_format": "mp4",

       // 可选：是否额外返回末帧图片；默认 false。
       // true：通过查询接口获取末帧 JPEG，尺寸与视频一致，图片无水印。
       "return_last_frame": false,

       // 可选，仅 2.5：样片模式，默认 false。
       // true：生成预览样片，resolution 必须改为 480p。
       // false：正常生成视频。
       "draft": false,

       // 可选：任务过期时间，单位秒；从任务创建时间开始计算。
       // 范围 3600～259200，默认 172800（48 小时）。
       // 到期后终止任务并标记为 expired。
       "execution_expires_after": 172800,

       // 可选：排队优先级，范围 0～9，默认 0；越大越优先。
       // 仅影响同一 Endpoint 内的排队顺序，不中断正在运行的任务。
       "priority": 0,

       // 启用联网搜索：2.5 / 2.0 系列支持，模型按需决定是否搜索。
       // 改为 [] 可关闭；实际次数见查询结果 usage.tool_usage.web_search。
       "tools": [
         {
           // 必需：工具类型，固定 web_search。
           "type": "web_search"
         }
       ]

       // 以下字段按需添加，注意补齐 JSON 逗号。

       // callback_url：接收任务状态变化通知的回调地址。
       // 示例："callback_url": "https://example.com/video-callback"

       // safety_identifier：终端用户稳定唯一标识，英文字符串，不超过 64 字符。
       // 官方建议使用用户 ID 等信息的哈希值，避免直接传个人信息。

       // service_tier：本例省略，不在此 JSON 中添加该字段。
       // 官方该字段支持列表仅列 1.0 Pro / Pro Fast；2.5 / 2.0 系列不使用。

       // seed、camera_fixed、frames：官方支持列表未包含 2.5 / 2.0 系列，不传。
       // omni_reference_task_type：用于全模态参考任务类型引导，纯文生视频不传。
     }
   }
   ```

2. **调用脚本提交生成：** 脚本完成上述官方参数适配后，使用上一步构建的 JSON 对象通过 `python3 "$SKILL/scripts/main.py" submit` 提交生成任务。使用本次任务文件目录 `$WORK` 作为 `--workdir`。脚本校验通过后将已确认的完整请求保存为 `$WORK/payload.json`；每次提交及其输出分别保存为 `submit-NNN.json` 和 `output-NNN/`。任务文件目录、提交序号及记录文件由脚本管理；记录返回的当前序号，并将提交文件路径记为 `$SUBMISSION`，供后续使用，不自行递增编号或拼接路径。命令示例见脚本操作手册。
3. **判断生成结果：** 调用 `python3 "$SKILL/scripts/main.py" status` 检查生成任务状态；`queued`、`running` 表示尚未完成，继续查询同一任务，不重新提交。如果失败则提示用户，如果成功则继续交付。提交结果未知时按脚本操作手册的失败处理规则核对原任务。
4. **交付结果：** 调用 `python3 "$SKILL/scripts/main.py" deliver` 获取并校验生成结果，将最终视频交付到启动本技能时所在项目目录下的独立子目录，并返回交付文件清单。完成后进入主流程的内容核验与结果展示步骤。视频核验时，检查实测分辨率、时长、音轨及画面、对白、音效、事件顺序是否符合确认要求。API 返回的整数时长可能与文件实测时长不同，以文件实测为准。
