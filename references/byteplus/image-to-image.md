# BytePlus · 图生图（`operation=image-to-image`）

## 生成要求

### 参数要求

| 参数 | 必须性 | 可选项 / 默认值 |
|---|---|---|
| `prompt` | 必需 | 图片编辑提示词，对应 `optimized_prompt`；提交时须与确认单一致 |
| `size` | 必需 | `1K`、`1.5K`、`2K`，或准确像素 `宽x高`，例如 `1024x1024`。准确像素要求：宽×高为 921600～4624220，宽/高为 1/16～16；两项须同时满足。用户未指定时，默认 `1K` |
| `assets` | 必需 | 按确认顺序提供的图片素材列表，数量、格式及填写要求见下方“素材要求” |

### 素材要求

- 支持 JPEG、PNG、WebP、BMP、TIFF、GIF、HEIC、HEIF，每张图片不超过 30 MiB。
- 宽高均大于 14 px，总像素不超过 3600 万，宽高比为 1/16～16。
- 单图编辑提供 1 张图片；多图融合提供 2～10 张；局部编辑提供 1～10 张，其中待编辑图片与辅助参考图的用途须明确。
- 按确认顺序填写外层 `assets`，每项包含 `id`、`kind`、`source`、`purpose`，其中 `kind` 固定为 `image`。`source` 为本地绝对路径或可访问的 HTTPS URL，可混用；脚本按顺序处理素材，将本地图片编码为 Base64，并填入 `payload.image`。该字段留空数组或省略，不手工填写素材内容。

### 提示词优化

- 在生成确认单前，结合实际参考图使用 `sd25-pe` 优化提示词，仅应用与当前图片能力相关的规则，最终提示词须符合所选模型的要求；确认后的生成步骤不再改写提示词。
- 用户明确要求不优化时，按主流程将完整拼接的 `original_prompt` 原样赋给 `optimized_prompt`，不调用本地提示词优化，也不主动启用供应商服务端提示词优化。如所选模型无法关闭服务端优化，先说明限制并取得用户接受，再提交。
- 使用尺寸档位时，可在提示词中表达构图比例偏好，但不保证精确比例；需要准确比例时，通过符合限制的宽高像素落实。
- 根据实际编辑方式组织提示词：
  - **单图编辑：** 明确修改内容及保留内容，包括用户要求的外观、姿态、构图、背景、风格或文字等。
  - **多图融合：** 按输入顺序称“图片1”“图片2”等，逐张说明素材用途，以及融合后的主体关系、场景和构图；明确各图中需要保留的内容。
  - **局部编辑：** 明确修改区域、修改内容及区域外的保留要求。可用自然语言定位，或使用用户已标注的参考图；使用 `<point>x y</point>`、`<bbox>x1 y1 x2 y2</bbox>` 时，坐标须为 0～999 的归一化整数，框从左上到右下且面积非零，先核对实际区域，不编造坐标。此能力不提供独立 mask 参数，也不保证区域外像素完全不变；交付前仍需核验。

## 生成步骤

以下步骤在用户需要图生图且确认当前 BytePlus 方案后执行。

1. **构建任务 JSON：** 参考如下示例，基于用户输入的参数和确认的供应商、模型和能力，生成任务 JSON 数据。移除示例中的全部注释后，将严格 JSON 直接追加到下一步命令的标准输入中。以下示例为单图编辑；多图融合时按顺序扩展外层 `assets` 数组，在最终提示词中说明每张参考图的用途。局部编辑使用同一结构，将已核实的区域和保留要求写入提示词。

   ```jsonc
   {
     "provider": "byteplus", // 必需：供应商，供脚本选择对应适配器
     "operation": "image-to-image", // 必需：能力，供脚本选择接口及结果处理方式
     "original_prompt": "把图片背景改为草地，保留熊猫外观", // 流程记录：用户原始提示词，不提交给供应商
     "assets": [ // 必需：本方案使用的素材，按输入顺序排列，由脚本解析，不直接提交给供应商
       {
         "id": "panda", // 必需：任务内唯一标识，供供应商引用；不是供应商素材 ID
         "kind": "image", // 必需：image、video 或 audio；本能力仅接受 image
         "source": "https://example.com/panda.jpg", // 必需：执行前替换为实际 HTTPS URL 或本地绝对路径
         "purpose": "待编辑的熊猫图片，保留熊猫外观，只修改背景" // 必需：素材用途，只在这里记录一次
       }
     ],
     "payload": { // 必需：BytePlus 请求参数，脚本校验模型、参数及需求记录，解析外层 assets 并填充素材字段后提交，不改写提示词；调用约定见脚本操作手册“提交生成”
       // 必需：准确模型 ID，按已确认方案二选一。
       // Pro：dola-seedream-5-0-pro-260628，偏重图片质量。
       // Flash：dola-seedream-5-0-flash-260915，偏重速度与成本。
       "model": "dola-seedream-5-0-flash-260915",

       // 必需：明确修改项、保留项及各图片用途。
       // 读取当前 request.json 的 optimized_prompt，须与确认单一致，不再改写。
       // 单图编辑说明修改内容；多图融合按素材顺序说明“图片1”“图片2”的用途。
       // 局部编辑指明修改区域与区域外保留要求，无需额外的模式或 mask 字段。
       // 使用尺寸档位时，提示词中的比例为构图偏好，不保证精确比例。
       "prompt": "将图片1的背景替换为草地，保留熊猫外观和姿态。",

       // 由脚本根据外层 assets 按顺序填充；此处留空数组或省略，不手工填写素材。
       // 原生 API 支持单个图片字符串或字符串数组，内容为图片 URL 或 Base64 数据。
       // 技能的本地绝对路径填在 assets.source，由脚本编码，不直接传给 API。
       "image": [],

       // 必需：1K、1.5K、2K，或准确像素，例如 1024x1024。
       // 准确像素须同时满足：宽×高为 921600～4624220，宽/高为 1/16～16。
       // 用户未指定时，技能默认 1K；API 默认 2K。图生图不使用 auto。
       "size": "1K",

       // 必需，固定 png：图片文件格式。
       // API 可选 png、jpeg，默认 jpeg；技能固定输出 PNG。
       "output_format": "png",

       // 必需，固定 url：返回下载链接，生成后 24 小时内有效。
       // API 还支持 b64_json，直接返回 Base64 图片数据；API 默认 url。
       "response_format": "url",

       // 必需，固定 false：不添加可见水印。
       // API 可选 true、false，默认 true；true 在右下角添加“AI 生成”水印。
       "watermark": false,

       // 必需，固定 opaque：不透明背景，也是 API 默认值。
       // API 的 transparent 仅适用于输入一张带透明通道图片的图生图，且须输出 PNG。
       // 当前技能固定 opaque，不启用透明背景模式。
       "background": "opaque",

       // 必需，固定 false：普通图片生成，也是 API 默认值。
       // true 为图层拆分，必须提供一张输入图片，不适用于本例图生图。
       "layer_decomposition": false

       // optimize_prompt_options 固定省略，不在此 JSON 中添加该字段。
       // API 的 mode 默认 standard；Pro 支持 standard、fast，Flash 仅支持 standard。
       // standard 偏重质量；fast 降低耗时，效果可能略低。省略字段不表示关闭服务端优化。
     }
   }
   ```

2. **调用脚本提交生成：** 使用上一步构建的 JSON 对象通过 `python3 "$SKILL/scripts/main.py" submit` 提交生成任务。使用本次任务文件目录 `$WORK` 作为 `--workdir`。脚本校验通过后将已确认的完整请求保存为 `$WORK/payload.json`；每次提交及其输出分别保存为 `submit-NNN.json` 和 `output-NNN/`。任务文件目录、提交序号及记录文件由脚本管理；记录返回的当前序号，并将提交文件路径记为 `$SUBMISSION`，供后续使用，不自行递增编号或拼接路径。命令示例见脚本操作手册。
3. **判断生成结果：** 调用 `python3 "$SKILL/scripts/main.py" status` 检查生成任务状态，如果失败则提示用户，如果成功则继续交付。
4. **交付结果：** 调用 `python3 "$SKILL/scripts/main.py" deliver` 获取并校验生成结果，将最终图片交付到启动本技能时所在项目目录下的独立子目录，并返回交付文件清单。完成后按主流程核验内容并展示结果：检查修改是否符合要求、应保留的内容是否被误改；多图融合还须核验各参考图的主体特征及其组合关系。
